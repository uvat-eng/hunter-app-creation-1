# Инструкция: сборка Android-приложения для RuStore

Нативный Android-проект уже сгенерирован и настроен в папке `android/` — Capacitor,
иконки, разрешения и загрузочный экран готовы. Осталось скачать проект и собрать
подписанный файл в Android Studio на вашем компьютере (это шаг, который делается
только локально — see ниже почему).

## Что уже готово в проекте
- appId: `ru.hunterdiary.app.pro`, название: «Охотник»
- Нативный проект `android/` создан и синхронизирован (`npx cap sync` выполнен)
- targetSdkVersion 36 / minSdkVersion 24 / compileSdkVersion 36 — с запасом выше минимума RuStore (28)
- Иконка приложения (adaptive icon) и загрузочный экран (splash) — брендированные, на фирменном тёмно-зелёном фоне
- Разрешения на календарь прописаны в `AndroidManifest.xml`:
  `READ_CALENDAR`, `WRITE_CALENDAR` (для функции «добавить событие охоты в календарь телефона»)
- Политика конфиденциальности: `/privacy`
- Условия использования: `/terms`
- Графика для карточки в сторе: `public/app-store-assets/`
  - `play-feature-graphic.png` (1024×500) — баннер карточки
  - `android-adaptive-fg.png` — исходник иконки
- Иконка 512×512 для карточки: `public/icons/icon-512.png`

## Шаг 1. Скачайте код проекта
В интерфейсе poehali.dev: **Скачать → Скачать код**

## Шаг 2. Установите зависимости
```bash
cd hunter-app-creation-1
npm install   # или bun install
```
Папка `android/` уже входит в код проекта — `npx cap add android` заново запускать не нужно.

## Шаг 3. Требования на компьютере
- **Node.js версии 22+** (Capacitor CLI этого требует)
- Установленный **Android Studio** (https://developer.android.com/studio) — бесплатно, Windows/Mac/Linux
- Аккаунт разработчика в **RuStore Console** — https://console.rustore.ru
  (для ИП/юрлиц — через ЕСИА/Госуслуги, для физлиц — по паспорту, бесплатно)

## Шаг 4. Соберите веб-часть и синхронизируйте с нативным проектом
Каждый раз при изменении кода перед сборкой в Android Studio:
```bash
npm run build
npx cap sync android
```

## Шаг 5. Откройте проект в Android Studio и соберите подписанный файл
```bash
npx cap open android
```
Откроется Android Studio. Дальше:
1. Дождитесь синхронизации Gradle (может занять несколько минут при первом запуске)
2. Меню **Build → Generate Signed Bundle / APK**
3. **Для самой первой публикации выбирайте формат APK, а не AAB** — у RuStore ещё
   нет сохранённой подписи вашего приложения для сверки, поэтому AAB на первом
   релизе система не примет (форма загрузки явно просит: если подписи ещё нет —
   загружайте APK). Начиная со второго релиза можно использовать AAB — с тем же keystore
4. Создайте новый ключ подписи (Keystore) через мастер — **сохраните файл и пароли в надёжном месте**,
   он понадобится для всех будущих обновлений приложения
5. Соберите **Release**-версию

## Шаг 6. Публикация в RuStore
1. Зайдите в RuStore Console → **Добавить приложение**
2. Заполните карточку: название «Охотник», описание, категория «Спорт» или «Образ жизни»
3. Загрузите иконку 512×512 — `public/icons/icon-512.png`
4. Загрузите баннер карточки — `public/app-store-assets/play-feature-graphic.png`
5. Добавьте 2-8 скриншотов приложения (сделайте на реальном телефоне или в эмуляторе Android Studio)
6. Укажите ссылку на политику конфиденциальности: `https://ваш-домен/privacy`
7. В разделе **Версии → Загрузка версии приложения** перетащите собранный **.apk**-файл из Шага 5
   (поле «Подпись для загрузки AAB» на первом релизе не трогайте — оно нужно только начиная со второй версии)
8. Заполните комментарий для модератора при необходимости (например, тестовый логин, если он нужен для проверки)
9. На следующих шагах мастера (иконка, описание, скриншоты, разрешения) укажите причину запроса
   разрешений на календарь
10. Отправьте на модерацию (обычно занимает несколько дней)

## Почему сборку .aab нельзя сделать автоматически
Финальный шаг — подпись пакета собственным ключом (Keystore) — принципиально ручной
и должен выполняться на вашем компьютере: ключ никогда не должен покидать ваше
устройство, иначе вы потеряете возможность безопасно обновлять приложение в будущем.
Всё остальное (код, иконки, разрешения, нативный проект) уже подготовлено.

## Важные напоминания
- **Keystore-файл нельзя терять** — без него нельзя выпускать обновления существующего приложения в RuStore
- После любых правок в коде: `npm run build` → `npx cap sync android` → пересборка в Android Studio
- Bundle ID/appId везде должен совпадать: `capacitor.config.ts`, `android/app/build.gradle` (`applicationId`)
  и карточка в RuStore Console — `ru.hunterdiary.app.pro`
- Скриншоты для карточки делайте на реальном устройстве или через эмулятор Android Studio — это отдельная задача, не автоматизируется кодом

## Как выпускать обновления так, чтобы данные пользователей не терялись
Все данные приложения (профиль охотника, оружие, документы с фото, автомобиль, события охоты)
хранятся локально на устройстве в IndexedDB — это часть Android-хранилища приложения, привязанная
к его package name. Она сохраняется автоматически при обновлении через RuStore и **никогда не
стирается кодом приложения** — очистки хранилища при старте в проекте нет.

Чтобы обновление корректно "легло" поверх старой версии у пользователей, а не потребовало
переустановки (которая обнулила бы данные), при каждой новой сборке соблюдайте:
1. **Никогда не меняйте `applicationId`** в `android/app/build.gradle` (`ru.hunterdiary.app.pro`) —
   если сменить его хотя бы раз, для пользователя это будет уже другое приложение, старые данные
   станут недоступны.
2. **Всегда подписывайте новую сборку тем же keystore-файлом**, что и первую публикацию — иначе
   RuStore не примет обновление либо предложит пользователю удалить старую версию перед установкой.
3. **Перед каждой сборкой увеличивайте `versionCode`** в `android/app/build.gradle` минимум на 1
   (например, было 3 → станет 4). `versionName` — это просто "человеческий" номер версии (1.2, 1.3…),
   можно менять свободно, а `versionCode` обязателен именно как счётчик для магазина.
4. Функция "Сохранить / Восстановить" (если будет добавлена) нужна только для переноса данных
   на **другой телефон** — обычное обновление приложения через RuStore эту функцию не использует
   и не требует от пользователя никаких действий.
